# 影片：日期資料夾與畫質前綴

## 使用者已選定的格式

```text
指定根目錄/
  2026-08-25/
    [720H] 原檔名.mp4
  2026-09-11/
    [1080p] 原檔名.mp4
```

- 日期只出現在資料夾名稱，使用完整 `YYYY-MM-DD`，不要只用月份。
- 影片檔名只新增畫質前綴及一個空格；保留原標題、編號與副檔名，不再加日期、人物、片長或來源標籤。
- 保留既存的 `[同名2]` 等文字；不要因本技能而自動新增這類標籤。
- 收藏／下載日期以檔案建立時間作為代理。簡短說明它不一定等同原始下載日期；不要把修改時間、今天日期或網站發行日期當成下載日期。
- 按使用者時區轉換日期；Leo 的既定時區為 `Asia/Taipei`，有新的明確指定則依指定。macOS 可讀 `st_birthtime`；缺少可靠建立日期時保留原位置並列為未處理，不猜日期。
- 僅補画質時不要搬資料夾；僅調整日期資料夾時不要擅自改畫質。使用者要求整套整理才同時執行兩者。
- 只操作本次指定根目錄；不要沿用某次硬碟路徑、影片數或編號作為固定目標。只討論分類方法時不改檔。

## 畫質規則

對沒有已知畫質前綴的影片讀取實際影片軌解析度與時長。以解析度短邊分級：

| 短邊像素 | 前綴 |
| --- | --- |
| >= 2000 | `[2160p]` |
| >= 1300 | `[1440p]` |
| >= 1000 | `[1080p]` |
| >= 700 | 依下列位元率使用 `[720H]`、`[720M]` 或 `[720L]` |
| < 700 | `[480p]`（既有粗略分類，不代表精確解析度） |

720 級以估計總位元率 `檔案位元組 × 8 ÷ 秒數 ÷ 1000`（kbps）分類：

- >= 1500：`[720H]`
- >= 1000 且 < 1500：`[720M]`
- < 1000：`[720L]`

H/M/L 是沿用的位元率分級，不是人眼畫質評分。不要轉檔或修改影片內容。

可用既有 `ffprobe` 讀取中繼資料；macOS 未安裝時使用 Swift AVFoundation，無須為此安裝大型工具。優先採用 async `load` API。多影片軌時使用主要非封面影片軌；時長非正值、解析度無效或讀取失敗者不新增猜測的前綴，回報未處理。

已有 `[2160p]`、`[1440p]`、`[1080p]`、`[720H]`、`[720M]`、`[720L]`、`[480p]` 的影片不要重複加標籤；若發現既有標籤不符，回報差異，除非使用者要求修正。

## 執行與驗證

1. 掃描當下範圍的影片及現有子資料夾，排除 `._` AppleDouble 附屬檔、符號連結及非影片。記錄每個來源的完整路徑、大小、建立時間、修改時間，並在工作區 `work/` 保存來源到目的地的對照紀錄，讓操作可逆。
2. 先算好所有目的地並檢查同名碰撞、檔名長度與可讀寫性。以目標檔案系統實際限制為準，不任意截斷原標題。同名檔案不覆蓋、不刪除、不自動去重；保留該項原位並回報衝突，其他沒有衝突的項目照常完成。
3. 在同一磁碟內重新命名／搬移。若移除先前本次對話加錯的 `[YYYY-MM-DD]` 前綴，使用改名紀錄或明確指示確認其來源；不要只因原標題看起來像日期就刪除。
4. macOS 可能會隨影片搬移自動處理 `._` 附屬檔。每次搬移後重新確認：若原位置附屬檔還在且目的地不存在，才搬附屬檔；若已跟隨到新位置，不要再次搬移。不要把來源附屬檔消失直接當作整次操作失敗。
5. 若檔案系統不支援排他改名（例如 `renamex_np` 回報不支援），再次確認來源與目的地實際狀態後，才能使用平台支援的普通改名。執行期間不要平行修改同一批檔案；發生錯誤先依對照紀錄核對已完成的項目，不要盲目重跑並產生更多前綴。
6. 只移除此次整理留下的真正空資料夾，不刪除為了清空資料夾而遇到的隱藏檔或其他資料。
7. 重掃確認影片數量、每項目的地、原檔名保留、檔案大小與建立／修改日期一致，並確認附屬檔位置。新加的畫質前綴要與實測分級一致；執行整套整理後，完整日期只能是資料夾分類，不能額外加在影片檔名上。

最後簡短回報實際處理數、日期資料夾與各自影片數，以及尚未處理的衝突／未知項目。有未處理項目時不要宣稱全部完成。不要為基本檔案整理新增資料庫、媒體伺服器、網路查詢或自動監控。
