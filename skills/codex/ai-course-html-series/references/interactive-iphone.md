# 可操作的 iPhone 教學

## 目標與範圍

讓學員在手機外框內「點一下 → 看見介面反應 → 讀懂用途 → 自己試下一步」。這是依教學情境重建的操作示意，不必重造 iOS、完整 ChatGPT 或真正登入服務。

從現有 HTML、CSS 和少量 JavaScript 開始。只有已有架構確實需要時才引入框架。教材示意預設不使用 API、不需要帳號、不寫入真實行事曆。

使用者的視覺參考：[Instagram Reel](https://www.instagram.com/reel/DcOKMqWzFE3/)。2026-09-11 在瀏覽器觀察到其中的 Gmail 模擬介面，下面以不同顏色區分介面呈現、接收操作、管理畫面狀態。可借用「看得到操作與回饋的關係」這個教學方向，不推斷其實際技術架構，也不複製對方品牌或影片素材。

## 第一條適合驗證的流程

首頁 → 點「＋」→ 選單展開 → 點「照片」→ 示範相簿 → 選一張教學素材 → 回到對話看到附件。

第一主題現在已支援首頁 → 加號選單 → 照片快捷選擇 → 所有照片的直接點擊與返回。選中照片後加入對話的結果仍未製作，以下完整流程是後續擴充範例。相簿畫面屬於手機系統介面，若依當前實機驗證有不同流程，照實修正。可縮成「首頁 → 加號選單 → 功能說明」作為第一個可檢查版本，再擴充。

## 最小實作

- 保留外層目錄、進度、上方選項及說明區。手機框內用幾個明確狀態，例如 home、attach、photos、conversation；每個可按控制都對應一個確定動作。
- 靜態部分可以保留實拍底圖，按鈕用真正的 HTML button 覆蓋並設定無障礙名稱；需展開或捲動的區域用 HTML 重建。熱區按原圖比例定位，不與裝飾圈選混在一起。
- 精簡資料結構即可：狀態 id、可用按鈕、目的狀態、說明文字、轉場類型。沿用現有頁面或回合資料，無需另建流程編輯器、外掛系統或事件總線。
- 彈出的選單只動畫選單本身；不要把整張全螢幕截圖滑進來，連狀態列也一起移動。若只有兩張完整截圖，改用輕淡入淡出並如實稱為畫面切換。
- 熱區發現方式用滑鼠移入淡框／觸控顯示框與單次圈線呼吸，不靠反覆閃爍。回饋放底板小提示，1.5 秒後淡出，解說卡只保留功能內容。
- 點擊後立即有選取回饋，約 180–260ms 完成淡入／側欄滑入／底部面板展開。支援 reduced-motion，停用動畫後依然完成同樣動作。
- 說明在動作後更新：桌機在手機右邊，手機寬度在外框下方。若做浮動說明，靠近目標但避開下一個要按的控制，並可關閉。不要每點一下都用全頁 modal 打斷操作。
- 手機內容區獨立 overflow-y:auto；頂列與輸入列固定在框內，不固定到整張網頁。內部區域標示可捲動，鍵盤也可操作；不要攔截整頁的觸控或滾輪。
- 「返回」回到前一個教學狀態；「重播本段」重設此段。網頁歷史與手機內返回各自語意清楚，避免按關閉卻離開教材。
- 教材不處理的按鈕可不加入熱區，或短註「本段未示範」；不能做可按外觀卻沒有任何回應。
- 教材解說、畫面及示範照片保留在輸出檔案中，預設保持離線可開，不為動畫增加遠端依賴。

## 解說語氣

名稱：新增照片與檔案。

解說：把照片或檔案交給 ChatGPT，接著問它裡面的內容。

下一步：點「照片」，選一張活動通知。

將「用途」和「下一步」分開，避免用一大段文字教所有操作。模擬的 AI 回覆是教材預設內容，與原始實測紀錄分開呈現。

## 驗證範圍

每條新增路徑實際點到終點，測關閉、返回、重播、連點、轉場中操作、鍵盤、窄螢幕、手機內捲動和 reduced-motion。不需為單純色彩微調另建龐大測試系統。先完成一條可操作路徑，確認教學有效後再擴充頁面。
